# 高校竞赛发票全生命周期、组织层级与专项抽调规约手册 (Lifecycle & Extraction Guide)

本文档承载 `invoice-audit-master` 技能的深层业务组织架构、动态过渡池流转、双目录物理隔离架构、防光栅化失真标准以及财务细节核算规约。

---

## 1. 赛季层级、队伍与时间节点层级组织规约

### 1.1 26 赛季顶层分类（4 大业务单元）
1. `主赛`
2. `一队障碍`
3. `一队任务`
4. `二队任务`

### 1.2 三级提交归集硬性要求
用户提交单据时，系统必须严格按 `赛季 -> 队伍 -> 人员` 建立目录结构。凡缺少“队伍”或“人员”信息的，Agent 必须立刻主动拦截提问确认，严禁擅自猜测或散落放置。

### 1.3 “时间待标定”动态过渡池与双月提醒机制
1. **过渡目录命名**：各队伍下统一设立 `{队伍名}（时间待标定）`（例：`主赛（时间待标定）`、`一队障碍（时间待标定）`）；
2. **新发票归集流向**：上一个时间节点（如 `2026.10.29`）之后产生的新发票，统一规整入对应队伍的 `{队伍名}（时间待标定）` 中；
3. **动态阶段人员目录规范**：在时间节点未封闭前，人员文件夹保持纯名字（如 `何佳瑞`、`孙锦浩`），不带金额后缀；
4. **双月（约 2 个月）巡检提醒**：系统在日常交互中观察距离上次标定时间戳；满 2 个月（如 2026.12.29 前后）主动提醒用户：
   > “*当前时间节点已运行约 2 个月，请确认是否为【时间待标定】目录敲定正式时间节点？*”
5. **时间节点封闭与结算规约**：
   * **批次重命名**：由用户敲定日期后，批次目录更名为完整规范：`{队伍名}报销（YYYY.MM.DD）（支付{支付金额}_发票{发票金额}）`；
   * **人员目录追加金额**：系统批量核算各人员申报总额，自动为人员目录追加金额后缀：`{姓名}_{申报总额}`（例：`何佳瑞_1480.5`）；
   * **输出总账**：自动生成该批次标准 11 列 Excel 总账；
   * **循环新建过渡池**：封闭完成后，立刻在该队伍下新建下一个周期的空的 `{队伍名}（时间待标定）` 目录。

### 1.4 缓存区 (TEMP) 与全域动态池常态化巡检
* **强制纳入全盘审计池**：执行全盘发票查重、合规校验、总账复核或可用预算抽调时，系统必须强制将各赛季下的缓存区（如 `27赛季/TEMP`）纳入统一扫描范围，杜绝漏检漏查；
* **缓存区三分类管控机制**：
  1. **已闭环待建档**：发票与付款截图齐全，达到报销合规标准但尚未编入报销单，在下一次专项建档或批次封闭时优先吸收；
  2. **待补发票（差发票）**：仅有付款截图，统一强制追加 `_差发票` 后缀并导出待补清单，定向催促开具高校抬头发票；
  3. **跨库已迁移标记**：若缓存区物资已在正式库补齐发票并提报，源缓存区条目标记为 `_已迁移[队伍/主赛]正式库`，避免重复计算总额。

## 2. 专项报销包双文件夹标准架构 (Dual-Folder Separation Protocol)

为确保发票报销申报纸质单据整理与电子扫描归档绝对整洁，专项报销包根目录下**强制建立双文件夹分立架构**：

```text
比赛发票/
└── 两万报销单_已提交_10.30/                 # 专项报销包根目录
    ├── 1.物料与发票/                       # [第一业务域：按物料分类存放（对账与留底）]
    │   ├── 01-高压气泵_4403.7/             # 物料文件夹（两位补零前导）
    │   │   ├── 微信支付截图.jpg
    │   │   ├── 发票_499.50.pdf
    │   │   └── 发票_498.00.pdf
    │   └── ...
    │
    ├── 2.按金额排序发票PDF/                 # [第二业务域：发票原件池（贴票与交财务）]
    │   ├── 01-发票_4403.7_1.pdf
    │   ├── 02-发票_4403.7_2.pdf
    │   └── ...
    │
    └── 两万报销单总账（发票20000.00元）.xlsx   # 11 列总账总表
```

* **`1.物料与发票/`**：存放按采购项拆分的物料文件夹。内含该项物料的购买支付截图、订单明细截图及对应的一张或多张拆票 PDF/发票图片，供团队内部留底、核对实物与审计溯源；
* **`2.按金额排序发票PDF/`**：仅存放所有发票的原始 PDF 电子文件，按发票票面金额降序或对应序号排序重命名（格式：`{专包序号}-发票_{物料申报金额}_{分拆序号}.pdf`）。**专用于直接批量打印发票，供学生粘贴在财务报销单背面**，免去在各物料文件夹中逐个翻找发票的繁琐工作。

## 3. 发票原件保真与严禁光栅化渲染红线 (Anti-Rasterization Rule)

* **必须直接复制原始二进制 `.pdf`**：
  在将发票存入 `2.按金额排序发票PDF/` 或生成报销包时，**严禁通过 `pdf2image`、截图、Canvas 渲染或打印机将原始矢量 PDF 转换为图片（JPG/PNG）后再转回 PDF**；
* **红线成因**：
  光栅化会导致国家税务总局发票全国统一发票防伪底纹、OFD/PDF 电子签章矢量印章模糊失真，极易触发高校财务处退单拒收；
* **执行契约**：必须采用原生文件级直接复制（`shutil.copy2` / `Copy-Item`），保持发票哈希、原件清晰度与电子发票真伪查验特征 100% 原始保真。

## 4. 优惠券、红包差额与实物平替记账细则

### 4.1 优惠券与红包差额记账
* **核心记账公式**：
  $$\text{申报报销金额} = \text{实际支付金额（银行卡/微信实扣）}$$
  $$\text{平台差额} = \text{发票票面金额} - \text{实际支付金额}$$
* **标记规则**：
  实付金额小于发票金额（如发票 100 元，实付 95 元，含 5 元平台红包抵扣）时，文件夹命名必须追加 **`_优惠卷`** 标记；总账中“实际支付金额”填入 95 元，“发票金额”填入 100 元，“备注”显式注明“平台红包/店铺满减抵扣 5.00 元”。

### 4.2 实物平替发票与商家类目差异
* **业务场景**：
  部分定制机械加工件、特定电子散件商家无法开具对应专有名词发票，开具了“五金配件”、“办公用品”或“耗材”等平替发票；
* **记账规范**：
  1. 文件夹品名按**实际采购物料真实名称**命名；
  2. 总账“发票内容”按**发票开票票面实际类目**如实填写；
  3. “备注”栏严格标注：`【平替发票】实物为[真实品名]，商家开具为[票面品名]，已核实实物入库`，确保财务穿透式审计无缝合规。

## 5. 标准 11 列报销 Excel 总账格式规约

| 列序号 | 列名 | 数据类型与格式要求 | 说明 |
| :---: | :--- | :--- | :--- |
| **A** | **序号** | 整数 (1, 2, 3...)，居中 | 报销物料条目序号 |
| **B** | **品名规格** | 文本，左对齐 | 物料名称与详细规格参数 |
| **C** | **数量** | 文本/整数，居中 | 采购件数或批次单位 |
| **D** | **单价** | 数值（两位小数），右对齐 | 单件采购价格 |
| **E** | **发票内容** | 文本，左对齐 | 对应发票票面货物或应税劳务名称 |
| **F** | **发票代码** | 文本格式 `@`，居中 | 10位/12位发票代码（数电票可留空） |
| **G** | **发票号码** | 文本格式 `@`，居中 | 8位/20位发票号码，强制文本防截断 |
| **H** | **发票金额** | 数值（两位小数），右对齐 | 单张发票价税合计金额 |
| **I** | **实际支付金额** | 数值（两位小数），右对齐 | 微信/支付宝/银行卡实扣金额 |
| **J** | **开票单位** | 文本，左对齐 | 销售方/销售商家全称 |
| **K** | **备注** | 文本，左对齐 | 红包差额、平替说明、拆票说明或垫资人 |

* **卡片式合并规则**：当一项物料对应多张分拆发票时，A~E 列与 I 列自动执行跨行垂直居中合并（Merge Cells），H、F、G、J 列逐行明细展示；末尾自动追加公式合计行 `=SUM(...)`。
